# Module 082 authorization and governance

Super Administrators, Administrators, and Project Team Coordinators have organization-wide scope. Project managers can manage only projects for which they are the authoritative project manager. Authorized team leads may manage risks only for projects owned by project managers in their explicit reporting or team scope. Assigned project participants can view project risks, and assigned action owners may update only their own actions.

Cross-project-manager access fails closed. Department text is not an authorization source. Risk and action owners must be active users assigned to the project, except organization-wide administrators may select any active user. The actual session identity is retained separately from the effective View-As identity; View-As is read-only and cannot export.

Threat strategies are avoid, mitigate, transfer, accept, and escalate. Opportunity strategies are exploit, enhance, share, accept, and escalate. The API accepts the complete controlled union while preserving the selected risk type. Closure requires decision evidence. Realization requires decision evidence and supports a governed issue reference.
