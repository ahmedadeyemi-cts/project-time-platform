# Document preparation, operation timers and archive

Authorized Work Register uploads and intake-to-project associations now enqueue eligible documents in the existing private processing queue within the same transaction. Post-intake uploads enqueue when already linked to a project. Requests persist metadata only; private workers perform scanning, extraction, OCR and citation indexing. Closing the browser does not discard preparation. No external model is invoked on upload.

Admission records the real actor, rejects View-As, preserves visibility and AI-context consent, and deduplicates active jobs. Ready documents are reused. Failed, quarantined and cancelled jobs retain the existing explicit recovery process. The Work Register bridge resets readiness when file location, size or revision changes. The configured document service principal continues to admit older eligible documents; its configuration and queue permission remain required. Closed projects and chat attachments are excluded. Background admission does not invent identities or enable disabled workers.

The selected project shows Preparing documents, Ready for AI, SOW needed, Needs attention, Preparation paused or Archived plan. Existing unqueued documents say Ready to prepare. The read-only panel refreshes without replacing local edits, hides restricted filenames, and clears stale responses on project/identity changes. One AI Planner request uses the existing durable, bounded operation to continue after preparation. Prepared evidence reduces repeated work but does not promise zero model latency or unlimited waiting past the operation deadline.

AI Planner and AI Workspace share a visible elapsed timer above navigation. It starts during request submission, then uses server run timestamps; refresh restores it and completion freezes the duration. Interrupted status observation is explicit. Project Forge AI Studio gets a request timer across preparation retries. Its existing request-based generation requires the page to remain open and is not presented as resumable server work. Timers do not invent completion percentages or announce every tick to screen readers.

Archive membership follows canonical project status: closed, completed, cancelled, canceled or archived. The same records move from active portfolio to Archive without copying or deleting plans, working copies, versions, reviews or audit records. Authorized viewers retain access. Planner edits and baseline adoption are denied server-side until Work Register reopens the project. Project-row transaction locks serialize closure with working-copy saves, reviewed candidate application and final AI persistence. Existing reviewed artifact sharing/revocation remains governed by PM permission. Existing Module 065 closed-project notification exclusions are preserved.

Tests cover native readiness, PostgreSQL queue deduplication/rollback/closure, late AI completion, archive filters, timer math and React readiness/timer races. The exact feature scope is registered with the existing controller; deployment workflows, approval documents, production configuration and notification boundaries are unchanged. No new database migration is required.
