# Stage 2: Module 025 SOW/GSD output-standards baseline (samples + spec + tests)

- **Type:** chore
- **Depends on:** none
- **Contract:** `contracts/module025-output-standards.md` (freeze/enforce v1)

## Objectives

Answer the "understand what the generated documents look like, and lock them to our
standards" ask **without changing any runtime behavior**. Capture the *current, verified*
US Signal SOW/GSD output format as (a) a written standards spec, (b) committed golden
reference samples produced by the live exporters, and (c) test assertions that fail if the
output drifts. This is the guardrail the later template/preview stages build on: it defines
"correct" before anything starts reshaping output.

Read-only w.r.t. product behavior; additive files + tests only.

## What to build

1. **Standards spec — `docs/module025-sow-gsd-output-standards.md`.** Enumerate each
   guarantee in `contracts/module025-output-standards.md` with a **stable id** (e.g.
   `SOW-FONT-01`, `SOW-LETTERHEAD-01`, `SOW-PHASES-01`, `SOW-DRAFT-01`, `GSD-SHEETS-01`,
   `GSD-FONT-01`, `GSD-GUARDS-01`, `GSD-DRAFT-01`, `SAFETY-INJECTION-01`). Source the values
   from the live exporters — do NOT invent new formatting:
   - SOW `.docx`: Arial, black `000000`, **11pt body** (`w:sz=22`), heading sizes
     (Title 19 / Subtitle 13 / H1 15 / H2 12), US Signal letterhead PNG in header, footer
     "US Signal | Statement of Work | Page", phase order Plan→Design→Implement→Validate→Release
     with the standard subsections, "DRAFT - Not approved" marker on drafts.
   - GSD `.xlsx`: standard program fills the bundled 12-sheet `Module025StandardGsd.xlsx`
     (list all 12 sheet names); whole-book Arial; review/rate guard cells; draft `E1`="DRAFT"
     and blanked partial totals; HAEA = from-scratch layout.
   Note the provenance: values verified against `Module025SowGsdDocumentExporter.cs`
   (`styles.xml`, letterhead/footer, phase sections) and `Module025StandardGsdExporter.cs`.

2. **Golden reference samples.** Add a generator entrypoint to the existing
   `tests/Module025ExportTests` harness (it already runs the real exporters with
   `modelCalls=0`; it already has a `--prepare-template` mode) that writes deterministic
   sample `sample-sow.docx` and `sample-gsd.xlsx` (standard program) — and optionally an
   HAEA GSD — from a fixed, non-customer fixture engagement, to a stable committed path
   (e.g. `docs/samples/module025/`). Deterministic bytes where feasible (fixed dates/ids);
   where OpenXML/ClosedXML embed nondeterministic metadata, assert on extracted
   structure/parts rather than raw byte-equality.

3. **Standards assertions — extend `tests/Module025ExportTests/Program.cs`.** For each
   stable id in the spec, add or map an assertion against freshly generated output
   (build on the existing checks: it already asserts Arial+`000000` in `styles.xml`, the
   12-sheet layout, cell mappings, draft markers, and formula-injection safety). Make the
   spec ids traceable to test cases (comment or a small manifest).

## Interface contracts

- **Exposes:** `contracts/module025-output-standards.md` v1 (frozen); the standards spec doc;
  the golden samples; the id→test traceability. Later stages (preview; future template
  wiring) MUST honor these ids.
- **Consumes:** the live exporters (`Module025SowGsdDocumentExporter`,
  `Module025StandardGsdExporter`), `Assets/Templates/Module025StandardGsd.xlsx`, the existing
  `tests/Module025ExportTests` harness. Do NOT touch `.github/workflows/` (scaffold-owned CI).

## Testing requirements

- Every stable id in `docs/module025-sow-gsd-output-standards.md` has a corresponding passing
  assertion in `tests/Module025ExportTests`.
- Sample generation is deterministic/reproducible and runs offline (`modelCalls=0`); a second
  run reproduces equivalent samples (structure-level).
- No product/runtime code path changes; existing export suite stays green.

## Acceptance conditions

- [ ] `contracts/module025-output-standards.md` is frozen v1 and matches live exporter reality
- [ ] `docs/module025-sow-gsd-output-standards.md` enumerates every guarantee with a stable id

- [ ] Each stable id maps to a passing test in `tests/Module025ExportTests`; drift fails the build
- [ ] No runtime/product behavior change (docs + tests + samples only)
- [ ] Existing suite stays green; CI all-green
